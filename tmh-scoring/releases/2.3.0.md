# tmh-scoring 2.3.0 — per-run scoring settings

**Released** 21 September 2026
**Decision** Sensitivity is applied at Triage/Client Review level (Jonathan, 20 Sep 2026)
**Band impact** ZERO DIFFERENCES on 56,690 stored records

---

## What changed

Every threshold the scorers consult now comes from a `ScoringSettings` object
instead of a module-level constant. Pass nothing and you get `DEFAULTS`, which
is built from the same constants the module globals held, so nothing that was
scored before scores differently now.

New module: `tmh_scoring/settings.py`.

```python
from tmh_scoring import ScoringSettings
from tmh_scoring.two_layer import assess

assess(...)                                              # shipped calibration
assess(..., settings=ScoringSettings(phonetic_strong=0.86))   # this run only
```

## Why

Triage needs to ask "what would this run look like if the sound axis were less
fussy?" without changing what any other run scores, and without anyone in
Triage touching a global default. Before this release that was impossible. The
thresholds were module globals, so the only two ways to vary them were:

1. **Edit the package** — which changes every run, past and future, and is a
   global settings change. Global settings belong to R&D and to Jonathan
   alone; nothing in Triage may make one.
2. **Re-score in a subprocess with a patched module**, the way
   `tools/band_diff.py` compares implementations. This works offline but is
   wrong for Triage: it cannot run inside a web request, it duplicates the
   data path, and it discards the per-comparison breakdown (`r.components`)
   that the Search & Score Settings panel exists to show. You would get a
   different number back with no way to say why it changed.

So the thresholds move onto an object, and the object travels with the call.

## How settings propagate

Public entry points take `settings=`. Internally the active settings travel in
a `contextvars.ContextVar` set for the duration of the call.

The contextvar is the propagation mechanism, not the API, and it was chosen
over threading an extra argument through every private helper for one reason:
**the failure modes are not symmetrical.** A helper that forgets to pass
settings on inherits the caller's settings, which is correct. A helper that
forgets an explicit argument silently reverts to the defaults, which is a
wrong answer that looks right. This is scoring code and a client report is the
output, so the safe failure mode wins.

Contextvars are per-thread and per-task, so two concurrent runs at different
sensitivities cannot see each other's.

| Module | Function |
|---|---|
| `two_layer` | `assess`, `mark_similarity`, `trade_similarity`, `phonetic_score`, `orthographic_score` |
| `word_scoring` | `score_word_result`, `risk_from_score`, `mark_similarity_components` |
| `goods_similarity` | `goods_similarity` |
| `risk_model` | `assess_risk`, `mark_similarity_tier` |

`image_scoring` is untouched. Its thresholds have fields on `ScoringSettings`
(the `visual` compartment) but the scorer is not wired into any run yet, so
there is nothing to thread them into. Phase 2.

## Compartments

Fields are grouped into the six compartments staff see in Triage:

| Compartment | Staff label | Governs |
|---|---|---|
| `classes` | Classes | Nice-class fallback tiers where specifications are missing |
| `terms` | Terms & descriptions | specification overlap bands |
| `phonetic` | Sounds like | the sound axis and its damping |
| `orthographic` | Spelled like | edit-distance scores and the tier-3 gate |
| `fuzzy` | Looks/reads alike | written-form gates, token coverage, v1 difflib cutoffs |
| `visual` | Image similarity | pHash and CLIP cutoffs (not yet wired) |

`COMPARTMENT_FIELDS` maps each to its fields. 2.4.0's `sensitivity.py` uses
that map to turn a labelled step into a settings delta — Triage picks a step,
R&D owns what the step means.

## What is deliberately NOT configurable

Thresholds and gates are knobs. The **measurements** are not: edit distance,
syllable splitting, Soundex, the overlap coefficient, and the conflict matrix
in `risk_model.py` are the model. Changing any of those is a package release
with a band_diff, not a slider.

## Behaviour change: per-axis tier-3 gates

`mark_similarity` previously tested `axes_best >= 0.90`, where `axes_best` is
the maximum of the written, sound and spelling axes. It now tests each axis
against its own compartment's threshold:

```python
whole_like >= s.written_strong or phon_score >= s.phonetic_strong
    or ortho_score >= s.orthographic_strong or token_is_whole
```

At the defaults all three are 0.90, so this is identical — which the diff
proves. It matters at any other setting: "sounds like, less fussy" must not
also loosen spelling, or a compartment is not a compartment.

## Removals

`LEGAL_FORMS_AUDIT` and `LEGAL_FORMS_WATCH` are gone. They were the two flat
patterns that had drifted apart and caused **finding G**, kept unused through
2.2.0 so an unmigrated caller still imported. One caller had not migrated:
`audit_engine/criteria.py` used `LEGAL_FORMS_AUDIT` to label a word in the
ignored-words panel as structural or weak.

That is a **labelling** question, not a stripping question, and it now has a
function of its own: `ignore_words.is_structural(token)`. It folds every
jurisdiction's list into one set, deliberately unlike stripping — stripping
must be per-jurisdiction or a Norwegian `AS` eats an English preposition
(finding G), but labelling does not change what is searched, and the union can
only move a word from "weak" to "structural", i.e. from offered-back to
not-offered-back. A word wrongly offered back is a staff member unignoring
`LTD` and wondering why their search filled with noise. A word wrongly
withheld is a missing link. The safe direction is the union.

## Also named

`word_low_medium_min` (6) was a bare literal inside `risk_from_score`'s `if`.
It now sits beside `word_high_min` and `word_medium_min` where it can be seen.

`generic_guard_ratio` (0.60) was a bare literal in `risk_model`'s
generic-vocabulary guard — the rule that stops SWIFT COURIERS and RAPID
COURIERS resembling each other through the word they share.

`TOKEN_COVERAGE_FOR_WHOLE` and `SOUNDEX_MIN_LENGTH_RATIO` remain importable
from `two_layer` but are now aliases of the corresponding `DEFAULTS` fields,
so there is one source of truth and no second copy of either number.
