## 1. Ignore-word lists move into the package

New `tmh_scoring/ignore_words.py`. `WEAK_TOKENS` (21 tokens) came from
`audit_engine/criteria.py`, which was the only copy. The three call sites now
import from the package: `audit_engine/criteria.py`,
`audit_engine/companies.py`, `uk_monitor/companies.py`.

**The two legal-form patterns were NOT the same, and are NOT unified here.**
Moving them is what revealed it. They had drifted in both directions:

| | audit engine | Watch |
|---|---|---|
| only this side has | HOLDINGS, GROUP, UK, (UK), L.L.C | CORPORATION, CORP, GMBH, SARL, BV, NV, AB, AS, SA, SL, SPA, SRL, PTY, CIC, LLC |

Both are kept, named `LEGAL_FORMS_AUDIT` and `LEGAL_FORMS_WATCH`, each wired
to the product that has always used it — so this release changes no score —
and a third, `LEGAL_FORMS_COMMON`, holds the forms both agree on for anything
written from here on. Equivalence proved on 1,183 distinct real mark and
company names from the Watch ledger: **0 differences** between each old
pattern and its moved twin.

**Finding G, awaiting a ruling.** The two patterns disagree on **27 of those
1,183 names (2.3%)**, and the audit side looks wrong on the evidence:

    'UK & FRIED CHICKEN'   audit -> '& FRIED CHICKEN'   watch -> 'UK & FRIED CHICKEN'
    'UK Health Radio ...'  audit -> 'Health Radio ...'  watch -> 'UK Health Radio ...'
    'HIFU CLINICS UK'      audit -> 'HIFU CLINICS'      watch -> 'HIFU CLINICS UK'
    'SKYEX.co.uk'          audit -> 'SKYEX.'            watch -> 'SKYEX. uk'

Stripping UK, GROUP and HOLDINGS eats words that are load-bearing in British
marks. Against that, Watch's bare `AS` and `SA` eat ordinary English
("SHOP AS YOU GO LIMITED"), so neither list is simply right. Unifying moves
scores on both sides and needs Jonathan's ruling.

## 2. The mark scorer returns its components

`word_scoring.mark_similarity_components()` is new and reports every
comparison made — method (`exact`, `starts_with`, `contains`, `fuzzy`,
`phonetic`), phrase, points, and reason — including comparisons that scored
nothing, because "we tried sounds-like and it scored 0" is the answer to most
questions staff ask about a result and was previously unanswerable.

`_mark_similarity_points()` now picks the best entry from exactly that list
rather than computing its own, so the total and the breakdown cannot drift.
Order and the strict `>` comparison are preserved, which is why first-best
still wins and the diff is zero.

Worked example (criteria: Exact NELA, Similar NEELER, Sounds Like NAYLA,
Contains NEL):

    'NELA'            total 4   exact 4 · fuzzy 0 · phonetic 2 · contains 0
    'NAYLAR LIMITED'  total 2   exact 0 · fuzzy 0 · phonetic 2 · contains 0

## Also in this release (outside the package)

`Scoring_Version` and `Threshold_Version` are no longer hard-coded strings:
both derive from `tmh_scoring.__version__` (`uk_monitor/_compat.py` exports
`SCORING_PACKAGE_VERSION`). Audit runs gained a `scoring_version` column
(migration 007) and stamp it. Before this, nothing recorded which code scored
a stored band.
